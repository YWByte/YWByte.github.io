本篇用同一个例子贯穿始终。下面这个函数有 bug：传入空列表时会除以零。

def mean(xs):
    return sum(xs) / len(xs)

# 测试：mean([]) == 0，mean([1, 2, 3]) == 2

我们把函数体清空，让模型从光标处开始重新写：

def mean(xs):
    ▌

它可能写出很多种代码，有的能通过测试，有的不能。我们关心的问题是：如果只能告诉模型“过了”或“没过”，它能不能学会修这个 bug？回答这个问题之前，需要先看清楚模型本身是什么。

0前置：下一个 token 的分数从哪里来

后面所有的训练，最终改变的都是“下一个 token 选谁”的概率。所以先把这个概率怎么算出来讲清楚。Transformer 内部的注意力机制这里不展开，只看它的最后一步：怎样从一个向量变成每个 token 的分数。

0.1每个位置都有一个向量

输入 def mean(xs): 会先被切成 token，比如 def、mean、(、xs、)、:。每个 token 先查表变成一个向量，然后依次经过很多层 Transformer。每一层都会让每个位置的向量吸收上下文的信息：xs 这个位置的向量，会逐渐带上“它是函数参数”“它多半是一个列表”这样的信息。

经过最后一层后，每个位置都有一个最终向量 \(h_1, h_2, \ldots, h_t\)。这些向量叫做隐状态。“隐”的意思是它们不是直接输出给人看的东西，而是模型内部的中间表示。

0.2为什么只取最后一个位置

GPT 这类模型做的是因果注意力：每个位置只能看到自己和它前面的 token。于是第 1 个位置只知道 def，第 3 个位置只知道 def mean (，只有最后一个位置 : 看到了完整的 def mean(xs):。

要预测 : 后面写什么，当然要用看到信息最全的那个向量，也就是最后一层、最后一个位置的隐状态：

$$h = h_t$$

这里有两个“最后”，含义不同。“最后一层”是指 Transformer 堆叠的层数方向，取加工得最充分的那一层；“最后一个位置”是指序列的长度方向，取看到上下文最完整的那个 token。两者交叉处的这一个向量，就是 \(h\)。

可以把 \(h\) 理解成模型对一个问题的回答：看完目前的上下文，下一步应该写什么样的东西？它不是某个具体的 token，而是一串数字，描述“接下来需要的东西有什么特征”。

0.3一个三维的玩具例子

真实模型里，\(h\) 有几千维，比如 4096 维。为了能手算，我们假设它只有 3 维，并且暂时给每一维起个名字：

  • 第 1 维：这里是否需要一个条件判断；
  • 第 2 维：这里是否应该立刻结束函数；
  • 第 3 维：这里是否和“空列表”这种边界情况有关。
注意

真实模型的维度通常没有这么干净的含义。一个概念往往分散在很多维上，一维也往往同时参与很多概念。这里给维度命名，只是为了让点积的计算有直观的读法，机制本身和真实模型完全一样。

假设模型读完 def mean(xs): 之后，算出的隐状态是：

$$h = [\,0.9,\ 0.1,\ 0.8\,]$$

按上面的命名来读：很需要条件判断，不太需要立刻返回，和空列表关系很大。这正是一个“意识到要先处理空列表”的状态。

0.4输出矩阵：每个 token 一行

有了 \(h\)，还要知道它和词表里每个 token 的关系。这件事由输出矩阵 \(W\) 完成，它也常被叫做 LM head 或 unembedding。假设词表只有 4 个 token，\(W\) 就有 4 行，每行是一个 3 维向量，对应一个 token：

token这一行的向量 \(w_i\)按维度的读法
if\([\,1.0,\ 0.0,\ 0.5\,]\)强烈对应条件判断，也和边界情况有关
return\([\,0.2,\ 1.0,\ 0.1\,]\)主要对应结束函数
try\([\,0.3,\ 0.0,\ 0.6\,]\)和异常、边界情况有一定关系
pass\([\,-0.5,\ 0.2,\ -0.3\,]\)和当前需要的东西基本相反

这里要区分两种东西。\(h\) 是每次计算出来的，换一段上下文就会变；\(W\) 是训练学到的参数，推理时固定不变。\(W\) 的每一行记录的是：什么样的上下文适合输出这个 token。

0.5点积就是逐个打分

要判断 if 适不适合当前上下文，就拿 \(h\) 和 if 那一行做点积：对应维度相乘，再加起来。

$$z_{\texttt{if}} = 0.9 \times 1.0 + 0.1 \times 0.0 + 0.8 \times 0.5 = 1.30$$

逐项看这个式子。第 1 维：上下文很需要条件判断（0.9），if 恰好擅长条件判断（1.0），贡献 0.9。第 3 维：上下文和空列表相关（0.8），if 也和边界情况相关（0.5），贡献 0.4。第 2 维：上下文不太需要返回（0.1），if 在这一维是 0，贡献 0。

每一项都是“上下文需要多少”乘以“这个 token 提供多少”。两者都大，这一项就大；一正一负，这一项就是负的，会把分数往下拉。对其他三个 token 做同样的计算：

$$\begin{aligned} z_{\texttt{return}} &= 0.9 \times 0.2 + 0.1 \times 1.0 + 0.8 \times 0.1 = 0.36 \\ z_{\texttt{try}} &= 0.9 \times 0.3 + 0.1 \times 0.0 + 0.8 \times 0.6 = 0.75 \\ z_{\texttt{pass}} &= 0.9 \times (-0.5) + 0.1 \times 0.2 + 0.8 \times (-0.3) = -0.67 \end{aligned}$$

return 分数不高，因为它擅长的“结束函数”恰好是当前上下文不需要的。pass 的每一维都和需求反着来，所以得到负分。这些分数叫做 logit。

0.6“乘以 \(W\)”就是一次做完所有点积

上面一行一行地算了 4 次点积。把 4 行叠成矩阵，这 4 次点积就是一次矩阵乘向量：

$$z = W h = \begin{bmatrix} 1.0 & 0.0 & 0.5 \\ 0.2 & 1.0 & 0.1 \\ 0.3 & 0.0 & 0.6 \\ -0.5 & 0.2 & -0.3 \end{bmatrix} \begin{bmatrix} 0.9 \\ 0.1 \\ 0.8 \end{bmatrix} = \begin{bmatrix} 1.30 \\ 0.36 \\ 0.75 \\ -0.67 \end{bmatrix}$$

矩阵乘向量的结果，第 \(i\) 个分量正是第 \(i\) 行和向量的点积，也就是 \(z_i = w_i^\top h\)。形状上，\(W\) 是 \(4 \times 3\)（4 个 token，每个 3 维），\(h\) 是 3 维，\(z\) 是 4 维，每个 token 一个分数。

真实模型只是规模更大。词表有 15 万个 token、\(h\) 有 4096 维时，\(W\) 就是 \(150000 \times 4096\) 的矩阵。“最后一层的隐状态 \(h\) 乘以输出矩阵 \(W\)”说的就是：拿当前上下文的向量，同时和词表里 15 万个 token 各做一次点积，得到 15 万个分数。

0.7从分数到概率

logit 可以是负数，加起来也不等于 1，不能直接当概率用。下一节会详细讲的 softmax 把它们变成概率：先对每个分数取指数让它变成正数，再除以总和让它们加起来等于 1。代入上面的分数：

tokenlogit \(z_i\)\(e^{z_i}\)概率
if1.303.6747.5%

return0.361.4318.5%
pass−0.670.516.6%

指数之和是 7.73，每个 \(e^{z_i}\) 除以 7.73 就是概率。到这里，模型完成了一次“预测下一个 token”：上下文 → 隐状态 \(h\) → 和每个 token 做点积得到 logit → softmax 得到概率。

可以试几件事。点“想直接返回”，第 2 维变大，return 的点积随之上升，成为最可能的 token，这就是模型写出那段有 bug 的 return sum(xs) / len(xs) 时的状态。点“什么都不想”，\(h\) 接近零向量，所有点积都接近 0，四个 token 的概率接近平均：上下文没有提供任何倾向，模型也就没有偏好。再把第 3 维拉到负数，pass 在这一维是负的，负负得正，它的分数反而会上升。

0.8训练改变的是哪些东西

假设在这个上下文下，我们希望模型输出 if。训练会提高 \(z_{\texttt{if}}\)，压低其他 token 的 logit。由于 \(z_{\texttt{if}} = w_{\texttt{if}}^\top h\)，有两条路可以做到：

  • 改 \(W\)：把 \(w_{\texttt{if}}\) 往 \(h\) 的方向挪一点，让 if 这一行更像“这种上下文”。同时把其他行往远离 \(h\) 的方向挪一点。
  • 改 Transformer 内部的参数：让模型以后读到类似的代码时，算出的 \(h\) 更靠近 \(w_{\texttt{if}}\)。

两条路由反向传播同时完成，调整量由梯度决定。第 2 节会推导这个梯度的具体形式。现在只需要记住一点：无论是监督学习还是强化学习，训练最终都落在“调整 logit，从而调整概率”上。两者的区别只在于，用什么信号决定哪些 logit 往上调、哪些往下调。

后面的章节会反复把注意力放在 logit 和概率上，Transformer 内部的细节则被看成一个整体：输入上下文，输出一个 \(h\)，再经 \(W\) 和 softmax 变成概率。这个整体，就是后文所说的模型，在 RL 里也叫策略。

1模型输出的是一个分布

1.1从 logit 到概率

上一节看到，最后一层、最后一个位置的隐状态 \(h\) 乘以输出矩阵 \(W\)，得到一个长度等于词表大小的向量，每个 token 一个分数：

$$z = W h, \qquad z \in \mathbb{R}^{|V|}$$

这些分数就是 logit。它们可以是任意实数，本身没有概率含义。把它们变成概率的是 softmax：

$$p_i = \frac{e^{z_i}}{\sum_j e^{z_j}}$$

softmax 做了两件事：取指数保证每个值都是正数，再除以总和保证加起来是 1。于是我们得到一个分布：在当前前文下，下一个 token 是每个候选的概率。

在光标处，模型的输出可能长这样。为了看得清楚，下面只保留 5 个候选 token。拖动左边的滑块改变 logit，看右边的概率怎么变化：

先不动温度，只拖 logit。有三个性质值得记住。

概率此消彼长。只拉高 if 的 logit，其他所有 token 的概率都会下降，因为分母变大了，而总和必须是 1。这意味着，提高一个 token 的概率，一定等于压低其他 token 的概率。

只有 logit 之间的差值有意义。把所有 logit 同时加上同一个常数 \(c\)，分子分母都乘以 \(e^c\)，概率完全不变。所以单看某个 logit 是 1.8 还是 5.0 没有意义，要看它比其他 logit 高多少。两个 token 的概率之比只取决于 logit 之差：

$$\frac{p_i}{p_j} = e^{z_i - z_j}$$

logit 每相差 1，概率之比就相差约 2.7 倍；相差 3，概率之比约 20 倍。

概率低不等于不会出现。默认设置下 try 的概率约 0.11。点几次“抽 20 次”，你会发现它经常出现一两次。这件事看起来平常，但它是第 7 节里模型能够学习的前提：模型只有偶尔写出某种代码，才有机会知道这种代码好不好。

1.2采样与温度

得到分布之后，生成时要从中选出一个 token。有两种基本做法：

  • 贪心解码：每次选概率最大的那个。同一个 prompt，永远得到同一个输出。
  • 采样：按概率随机抽。概率 0.52 的 token 大约一半的时候被选中，概率 0.11 的大约十次里出现一次。

RL 训练时用的是采样。原因在上一段已经提到：如果总是贪心，模型永远只写同一段代码，就没有机会发现别的写法可能更好。

采样前通常还会把 logit 除以一个温度 \(T\)：

$$p_i = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}}$$

拖动图 1 的温度滑块：

  • \(T < 1\) 时，logit 之间的差距被放大，分布变尖，高概率的 token 更占优势。\(T \to 0\) 就退化成贪心。
  • \(T > 1\) 时，差距被缩小，分布变平，低概率的 token 更容易被抽到。

默认 logit 下，\(T = 0.5\) 时 try 的概率从 0.11 降到 0.03；\(T = 2\) 时升到 0.16。温度是一个控制“多大胆子去尝试”的旋钮，RL 训练里通常设为 1，也就是直接使用模型本来的分布。

1.3一整段代码的概率

上面只看了一个位置。模型写一段代码，是一个 token 一个 token 地生成的：每写出一个 token，就把它接到前文后面，再预测下一个。

记 prompt 为 \(x\)，生成的 token 依次是 \(y_1, y_2, \dots, y_T\)。整段输出的概率，按链式法则等于每一步条件概率的乘积：

$$\pi_\theta(y \mid x) = \prod_{t=1}^{T} \pi_\theta(y_t \mid x, y_{<t})$$

这里 \(\pi_\theta\) 就是模型，\(\theta\) 是它的全部参数，\(y_{<t}\) 表示第 \(t\) 步之前已经写出的 token。之后我们会一直用 \(\pi_\theta\) 这个记号，它既表示“模型”，也表示“模型给出的概率”。

举个例子。假设模型写出 if not xs: return 0，第一步选 if 的概率是 0.3，第二步在 if 后面选 not 的概率是 0.4，后面的 token 都几乎是确定的，概率接近 1。那么整段代码的概率约是 \(0.3 \times 0.4 = 0.12\)。

1.4为什么总是取对数

一段几百个 token 的输出，概率是几百个小于 1 的数相乘，很快就会小到浮点数表示不了。所以实际计算时总是取对数，把乘积变成求和：

$$\log \pi_\theta(y \mid x) = \sum_{t=1}^{T} \log \pi_\theta(y_t \mid x, y_{<t})$$

取对数还有一个好处：每个位置的贡献变成了相加的独立项。后面会看到，无论是监督微调还是强化学习，loss 都是对每个位置的 \(\log \pi\) 做加权求和，区别只在于权重是什么。

本节的结论很简单：

模型在每个位置给出一个分布。训练模型，就是调整参数，让某些 token 的概率变高、另一些变低。

之后的所有方法，回答的都是同一个问题：该推高哪些 token，推多少。

2监督微调在做什么

2.1交叉熵 loss

先看最熟悉的情况：我们有一份标准答案。比如人类工程师写的修复是 if not xs: return 0，这一整段代码就是标准答案。把它切成 token 后，每个位置都对应一个正确的 token，本文把它叫作这个位置的目标 token。光标处的目标 token 是 if，下一个位置的目标 token 是 not，依此类推。

记住这个区分：标准答案指整段输出，目标 token 指某一个位置上的那一个 token。前者的概率是一串条件概率的乘积，后者的概率只是某个位置 softmax 分布里的一格。

监督微调（SFT）希望整段标准答案的概率尽可能大。由 1.3 节，它等于每个位置上目标 token 概率的乘积；由 1.4 节，取负对数之后变成每个位置的项相加：

$$-\log \pi_\theta(y \mid x) = \sum_{t=1}^{T} \underbrace{-\log \pi_\theta(y_t \mid x, y_{<t})}_{\text{第 } t \text{ 个位置的 loss}}$$

整段 loss 只是各个位置的 loss 相加，所以可以先只研究一个位置，弄懂之后再加起来（2.4 节做这件事）。下面固定在光标处：前文是 def mean(xs):，目标 token 是 if。这一个位置的 loss 是交叉熵：

$$\mathcal{L} = -\log p_{\text{target}}$$

这里的 \(p_{\text{target}}\) 是这一个位置的 softmax 分给目标 token if 的概率，也就是光标处概率分布里 if 那一格（0.29），不是整段标准答案的概率。本节和 2.3 节的 \(\mathcal{L}\)、\(p_k\) 都是这个单位置的量。

这个 loss 有一个直观的读法：目标 token 的概率越低，loss 越大，而且是急剧变大。概率 0.9 时 loss 约 0.11；概率 0.29 时约 1.24；概率趋近 0 时 loss 趋近无穷。模型越是“自信地错”，受到的惩罚越重。

2.2梯度长什么样

2.1 节给出了目标：让 \(\mathcal{L}\) 变小。但目标本身不告诉我们该怎么做。我们手里能动的是什么？在这一个位置上，loss 由 5 个 logit 决定：\(z_{\texttt{if}}, z_{\texttt{return}}, z_{\texttt{try}}, z_{\texttt{pass}}, z_{\texttt{\#}}\)。可以把它们想象成 5 个旋钮，每个旋钮都可以往上拧或往下拧。问题变成：每个旋钮该往哪个方向拧，拧多少？

最笨的办法是逐个试。当前 logit 是 \((1.2, 1.8, 0.2, -0.5, -1.0)\)。由 softmax，if 的概率是 \(e^{1.2} / (e^{1.2} + e^{1.8} + e^{0.2} + e^{-0.5} + e^{-1.0}) = 3.320 / 11.566 \approx 0.287\)，所以 loss 是 \(-\log 0.287 \approx 1.248\)（这里的 \(\log\) 是自然对数）。每次只把一个 logit 加 0.1，其余不动，看 loss 怎么变：

把哪个 logit 加 0.1新 lossloss 变化变化 ÷ 0.1

return1.302+0.054+0.54

这张表已经包含了我们要的全部信息。最后一列是“拧一点，loss 变多少”的比率，读法有两层：

  • 符号告诉方向。拧高 if 让 loss 下降，所以应该拧高它；拧高 return 让 loss 上升，所以应该反过来拧低它。
  • 大小告诉值得拧多少。return 的比率是 0.54，# 只有 0.03。动 return 对 loss 的影响是动 # 的十几倍，把力气花在影响大的旋钮上最划算。

当试探的步长趋近 0 时，这个比率就是导数 \(\partial \mathcal{L} / \partial z_i\)。5 个导数排成的向量叫梯度。于是优化手段就很自然了：每个旋钮都朝着让 loss 下降的方向拧，拧的幅度和它的导数成正比，也就是

$$z_i \leftarrow z_i - \eta \,\frac{\partial \mathcal{L}}{\partial z_i}$$

其中 \(\eta\) 是一个小的步长，叫学习率。导数为正就往下拧，导数为负就往上拧。这就是梯度下降。拧完以后，概率分布变了，导数也随之改变，于是再算一次、再拧一次，loss 一步步下降。

既然逐个试就能得到导数，为什么还要推公式？因为真实模型要调的不是 5 个 logit，而是几十亿个参数。逐个试意味着每个参数都要重新跑一次模型，代价完全不可接受。求导的意义在于：写出一个公式，一次就同时算出所有方向上的斜率。对 logit 的这一层，我们下面把公式推出来；更深的参数，则由反向传播沿着链式法则把这个结果继续往回传给 \(h\)、\(W\) 和 Transformer 内部。

推导分四步：先把 loss 写成 logit 的显式函数，才能对它求导；再分项求导；合起来得到梯度；最后取负号，得到每个 logit 实际被推动的方向。

第一步：把 loss 写成 logit 的函数。要对 logit 求导，loss 里必须直接出现 logit。现在 loss 里只有 \(p_k\)，所以先把 softmax 代进去。仍然只看光标这一个位置，\(z_i\) 是这个位置的 logit，目标 token 的下标为 \(k\)（即 if）。softmax 给出 \(p_k = e^{z_k} / \sum_j e^{z_j}\)，代入 loss：

$$\mathcal{L} = -\log \frac{e^{z_k}}{\sum_j e^{z_j}}$$

利用 \(\log(a/b) = \log a - \log b\) 拆开，再用 \(\log e^{z_k} = z_k\)：

$$\mathcal{L} = -z_k + \log \sum_j e^{z_j}$$

拆开以后，两项各有清楚的含义。第一项 \(-z_k\) 只和目标 token 有关：目标 token 的 logit 越大，loss 越小。第二项 \(\log \sum_j e^{z_j}\) 和所有 token 都有关：所有 token 的整体分数越高，loss 越大，其中分数高的 token 贡献最大，因为指数会放大它们。所以 loss 本身已经说明了训练要做什么：抬高目标 token，压低其他竞争者。

第二步：分别对两项求导。现在要算的，就是上面那张试探表最后一列的精确值：把 \(z_i\) 拧动一点点，loss 变化多少。\(i\) 可以是 if、return、try 中的任何一个。loss 是两项之和，和的导数等于各项导数之和，所以分开算。

第一项 \(-z_k\) 里只有目标 token 的 logit。如果 \(i = k\)，正在看的就是 if 本身，导数是 \(-1\)；如果 \(i \neq k\)，比如正在看 return，那么 \(-z_k\) 里根本没有 \(z_{\texttt{return}}\)，导数是 0。

第二项先把分母记作 \(S = \sum_j e^{z_j}\)，它就是 \(\log S\)。由链式法则：

$$\frac{\partial}{\partial z_i} \log S = \frac{1}{S} \cdot \frac{\partial S}{\partial z_i}$$

\(S\) 是所有 \(e^{z_j}\) 的和。对 \(z_i\) 求导时，只有 \(e^{z_i}\) 这一项会变，其余都是常数，所以 \(\partial S / \partial z_i = e^{z_i}\)。代回去：

$$\frac{\partial}{\partial z_i} \log \sum_j e^{z_j} = \frac{e^{z_i}}{\sum_j e^{z_j}} = p_i$$

最后一个等号正是 softmax 的定义。也就是说，分母那一项对某个 logit 的导数，恰好是这个 token 当前的概率。

第三步：合起来。两项导数相加：

$$\frac{\partial \mathcal{L}}{\partial z_i} = p_i - \mathbb{1}[i = k]$$

\(\mathbb{1}[i = k]\) 叫做指示函数：括号里的条件成立时等于 1，不成立时等于 0。所以这个式子对 if 是 \(p_{\texttt{if}} - 1\)，对其他 token 就是它们自己的概率 \(p_i\)。

还有一种更整齐的写法。把目标 token 写成一个 one-hot 的目标分布 \(y = (1, 0, 0, 0, 0)\)，那么所有分量合在一起就是：

$$\frac{\partial \mathcal{L}}{\partial z} = p - y$$

梯度就是模型当前预测的分布减去目标分布。预测和目标差多少，就修正多少。

第四步：取负号得到更新方向。梯度指向 loss 增大的方向。按梯度下降的规则 \(z_i \leftarrow z_i - \eta\, \partial \mathcal{L}/\partial z_i\)，logit 实际被推动的方向是负梯度：

$$-\frac{\partial \mathcal{L}}{\partial z_i} = \begin{cases} 1 - p_k & i = k \text{（目标 token）} \\ -p_i & i \neq k \text{（其他 token）} \end{cases}$$

代入例子。光标处的概率是 \(p = (0.29, 0.52, 0.11, 0.05, 0.03)\)，目标 token 是 if：

token当前概率 \(p_i\)更新方向 \(\mathbb{1}[i=k] - p_i\)含义
if0.29\(1 - 0.29 = +0.71\)往上推
return0.52\(-0.52\)被压得最多
try0.11\(-0.11\)被轻轻压一下
pass0.05\(-0.05\)几乎不动
#0.03\(-0.03\)几乎不动

这个结果会在本篇反复出现，值得逐条读懂。

对照前面的试探表：公式给出的 \(-0.71, +0.52, +0.11, +0.05, +0.03\)（取负号前的梯度）和试探得到的 \(-0.70, +0.54, +0.11, +0.06, +0.03\) 几乎一致。小的差异来自试探步长 0.1 不是无穷小。公式没有带来新信息，它只是把“逐个试”变成了一次就能算完的表达式。

目标 token 被往上推，力度是 \(1 - p_k\)。\(1 - p_k\) 是目标 token 离“概率等于 1”还差多少。if 现在是 0.29，还差 0.71，所以被大幅往上推；如果它已经是 0.99，只差 0.01，就几乎不再变化。模型已经学会的东西，梯度会自动变小，不需要人为干预。

其他 token 被往下压，力度是它们当前的概率 \(p_i\)。return 的概率是 0.52，它是 if 最主要的竞争者，所以被压得最多。# 只有 0.03，本来就很少被选中，压它也没什么意义，所以几乎不受影响。换句话说：谁从目标 token 那里抢走的概率越多，谁就被压得越狠。

所有分量加起来是 0。目标 token 增加 0.71，其他 token 一共减少 \(0.52 + 0.11 + 0.05 + 0.03 = 0.71\)，正好抵消。一般地，\((1 - p_k) - \sum_{i \neq k} p_i = 1 - \sum_i p_i = 0\)。原因是概率总和固定为 1，像一块大小不变的饼，训练只会把错误 token 手里的那份挪给目标 token。这和 1.1 节说的“只有 logit 之间的差值有意义”是同一件事：所有 logit 一起加上同一个数，概率完全不变，对降低 loss 毫无帮助，所以梯度里也不会包含这个方向。

继续点下去，if 涨得越来越慢。它离 1 越近，\(1 - p\) 越小，梯度也越小。loss 的数值也印证了这一点：前几步下降很快，之后越来越平。

旁注：logit 不是直接被更新的

图 2 为了看清楚，直接修改了 logit。真实模型里，logit 是 \(z = Wh\) 算出来的，被更新的是参数 \(\theta\)。梯度先到达 logit，再经过反向传播分配到每一层的参数上。所以“推高 if 的 logit”实际意味着：调整参数，使得在这个前文下算出来的 \(z_{\text{if}}\) 变大。这个区别在 2.5 节会变得重要。

2.4整段答案

回到整段标准答案。SFT 对其中每个位置都做一次 2.3 节的推动，推高该位置的目标 token，loss 是每个位置的交叉熵之和：

$$\mathcal{L}_{\text{SFT}} = -\sum_{t=1}^{T} \log \pi_\theta(y_t \mid x, y_{<t})$$

注意前文 \(y_{<t}\) 用的是标准答案的前文，而不是模型自己写出的内容。训练时，模型永远站在“前面都写对了”的位置上，预测下一个正确的 token。这种做法叫 teacher forcing。它让训练可以并行，一次前向就算出所有位置的 loss，但也埋下了 3.3 节要讲的问题。

比较 1.4 节的式子会发现，\(\mathcal{L}_{\text{SFT}}\) 恰好就是 \(-\log \pi_\theta(y \mid x)\)。也就是说，SFT 在做的事情，是最大化整段标准答案的概率。

2.5参数是共享的

图 2 里，每个 token 有自己独立的 logit，推高一个不会影响别的前文。真实模型不是这样。同一套参数要负责所有前文下的所有预测，推高“def mean(xs): 后面写 if”，会连带影响“def median(xs): 后面写什么”。

这种连带影响正是泛化的来源：在一个函数上学会“先检查空输入”，在相似的函数上也会更倾向这样做。但它也意味着更新不是局部的，学一个新东西可能会把别的东西改坏。后面讲遗忘、讲 KL 约束时，背后都是这个原因。

3监督微调的局限

SFT 简单、稳定、高效，大模型的后训练几乎都从它开始。但它对数据有一个很强的要求：每个位置都要有目标 token，也就是必须有一份完整的标准答案。这个要求带来几个绕不开的问题。

3.1正确答案不止一个

修这个 bug，至少有三种正确写法：

if not xs: return 0
return sum(xs) / len(xs) if xs else 0
try: return sum(xs) / len(xs)
except ZeroDivisionError: return 0

SFT 只能选其中一种当标准答案。如果选了第一种，那么在光标处，目标 token 是 if。按 2.2 节的梯度，return 和 try 都会被往下压，即便它们引出的代码同样正确。

模型因此学到的不是“怎样修好这个 bug”，而是“怎样写得像这份答案”。如果数据集里不同样本用了不同写法，模型就会在这些写法之间摇摆，并为此付出 loss。

3.2上限是示范者

SFT 的目标是让模型的分布接近示范数据的分布。如果训练完美，模型会和示范者写得一样，但不会更好。示范数据里没有的更优写法，SFT 没有任何机制去发现它。

对于简单任务，这不成问题。但对于需要长时间推理和试错的任务，比如修一个跨越多个文件的 bug，人类的示范数据又贵又少，而且示范者本身也会犯错。

3.3只见过正确的路径

这是最微妙、也最重要的问题。

2.4 节说过，SFT 训练时，模型总是站在“前面都写对了”的位置上。但生成时，前文是模型自己写的。只要某一步写偏了，后面的前文就是训练数据里从没出现过的状态。模型没学过在这种状态下该怎么办，很可能继续出错，越走越偏。

这个问题有个名字，叫 exposure bias：训练时暴露给模型的状态分布，和生成时它实际遇到的状态分布不一样。

可以粗略估算一下影响。假设模型在每一步都有 \(\varepsilon\) 的概率走偏，并且一旦走偏就回不来。那么连续 \(T\) 步都不出错的概率是：

$$(1 - \varepsilon)^T$$

拖动下面的滑块感受一下：

每步 99% 正确，听起来很好。但 100 步之后，全程无误的概率只剩 37%；300 步之后不到 5%。agent 任务动辄几十轮工具调用、几万个 token，这个问题会被放大到无法忽视。

真实情况没有这么悲观：模型走偏后有时能自己纠正回来。但关键在于，纠错能力恰恰需要在“已经出错”的状态下练习，而 SFT 的数据里几乎没有这样的状态。

3.4判断比示范便宜

换个角度看，我们手里其实还有一样东西：测试。

写出正确代码很难，判断代码对不对却容易得多，跑一下测试就知道了。很多任务都有这种不对称性：数学题有标准答案可以核对，代码有测试，搜索任务可以核对最终答案，网页操作可以检查页面最终状态。

测试不告诉你该怎么写，只告诉你写得对不对。而且它对三种正确写法一视同仁，都给通过；它也不要求模型像谁，只要求结果正确。

如果模型能只靠这种“对或不对”的反馈来学习，3.1 到 3.3 节的问题都有可能解决：

  • 不需要唯一的标准答案，任何能通过测试的写法都算对。
  • 不受示范者水平限制，只要能写出更好的代码，就会被奖励。
  • 模型在自己写出的内容上学习，会接触到自己真正会走到的状态，包括出错后的状态。

这就是强化学习要做的事。

4强化学习的基本语言

4.1智能体与环境

强化学习描述的是一个循环：智能体观察当前状态，选择一个动作；环境根据这个动作进入新状态，并可能给出一个奖励。智能体的目标是让累积的奖励尽可能多。

经典的例子是下棋或玩游戏：状态是棋盘，动作是落子，奖励是最终输赢。这些概念放到语言模型上，每一个都有具体的对应：

概念记号在修 bug 的例子里
策略\(\pi_\theta\)模型本身。给定前文，它决定下一个 token 的概率分布。
状态\(s_t\)prompt 加上已经写出的 token，也就是模型此刻看到的全部内容。
动作\(a_t\)下一个 token。动作空间就是整个词表。
状态转移把选中的 token 接到前文后面。这一步是确定的。
轨迹\(\tau\)从 prompt 开始到生成结束的完整序列，也叫一次 rollout。
奖励\(R(\tau)\)跑测试：通过得 1，失败得 0。

“策略”这个词听起来抽象，但它就是我们在第 1 节看到的东西：在每个状态下，给每个动作一个概率。之前说“模型”和“\(\pi_\theta\)”，现在可以说“策略”，指的是同一个对象。

4.2两种看待方式

同一个生成过程，可以从两个粒度来看。

token 级：每生成一个 token 就是一步决策，一段代码由几十上百步组成。这个视角下，奖励只在最后一步出现，前面每一步的奖励都是 0。

序列级：把整段输出看成一个动作，模型一次性“选”出一整段代码，然后立刻得到奖励。这个视角下，问题变成了：在所有可能的输出里，模型应该把概率分给哪些。

两种视角在数学上等价，因为整段输出的概率就是每一步概率的乘积。本篇主要用序列级视角推导，因为它最简单；推导完再拆回 token 级，看每个 token 受到了什么影响。到 agent 的场景里，模型和环境要来回交互很多轮，token 级视角会变得必要，那是后面的内容。

4.3目标函数

模型每次写出的代码不一样，有时通过有时不通过。所以“写得好不好”不能用某一次的结果衡量，要看平均水平。强化学习的目标是最大化期望奖励：

$$J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta}\big[R(\tau)\big]$$

式子里有三样东西。\(\tau\) 是模型完整写出的一段代码，也就是一条轨迹。\(\pi_\theta(\tau)\) 是参数为 \(\theta\) 的模型写出这段代码的概率。\(R(\tau)\) 是这段代码的奖励，通过测试得 1，没通过得 0。下标 \(\tau \sim \pi_\theta\) 读作“\(\tau\) 从模型的分布中采样得到”。整个式子的意思是：让模型按自己的概率写代码，平均下来能拿到多少奖励。

期望怎么算。把期望符号展开，就是把每一种可能的代码列出来，用“写出它的概率”乘以“它得到的奖励”，再全部加起来：

$$J(\theta) = \sum_{\tau} \pi_\theta(\tau)\, R(\tau)$$

这和掷骰子求平均点数是同一种算法：\(\tfrac16 \times 1 + \tfrac16 \times 2 + \cdots + \tfrac16 \times 6 = 3.5\)。不同的只是，这里骰子的每一面换成了一段代码，每一面的概率由模型决定，每一面的“点数”由测试决定。

假设模型在光标处只会写出 4 种补丁（第 6 节还会用到这组数字）：

模型写出的代码 \(\tau\)概率 \(\pi_\theta(\tau)\)奖励 \(R(\tau)\)乘积
if not xs: return 00.210.2
if xs is None: return 00.300
return … if xs else 00.110.1
return sum(xs) / len(xs)0.400

把最后一列加起来，\(J = 0.2 + 0.1 = 0.3\)。奖励只有 0 和 1 时，失败代码的乘积都是 0，期望就只剩“能通过的代码的概率之和”。所以 \(J = 0.3\) 有一个很直接的含义：模型随便写一次，有 30% 的概率通过测试。在这个例子里，期望奖励就是通过率。

表里每段代码的概率，来自 1.3 节：整段代码的概率等于每一步所选 token 的概率连乘，而每一步的概率又是第 0 节那条“\(h\) → logit → softmax”的链路算出来的。

\(J\) 为什么依赖 \(\theta\)。在 \(\sum_\tau \pi_\theta(\tau) R(\tau)\) 里，\(R(\tau)\) 是测试给出的结果，和参数无关：同一段代码，不管哪个模型写出来，测试结果都一样。依赖参数的只有 \(\pi_\theta(\tau)\)。所以训练无法改变某段代码“好不好”，只能改变模型“多常写出它”。

比如把 return sum(xs) / len(xs) 的概率从 0.4 降到 0.2，挪出来的 0.2 加给 if not xs: return 0：

$$J = 0.4 \times 1 + 0.3 \times 0 + 0.1 \times 1 + 0.2 \times 0 = 0.5$$

通过率从 30% 涨到了 50%。最大化期望奖励，就是把概率从得分低的代码挪到得分高的代码上。

实际中只能估计。这个例子只有 4 种代码，可以直接加完。真实模型能写出的代码多得无法枚举，所以实际训练时让模型采样写 \(N\) 次，用平均奖励来估计：

$$J(\theta) \approx \frac{1}{N} \sum_{n=1}^{N} R(\tau_n)$$

写 10 次通过 3 次，就估计 \(J \approx 0.3\)。再写 10 次，可能通过 2 次，也可能 4 次，所以这个估计会波动；采样越多，越接近真实值。“无法枚举”和“估计会波动”这两件事，分别是 5.3 节和第 6 节要处理的问题。

严格说，还应该对 prompt 取期望，因为训练时有很多不同的 bug 要修：

$$J(\theta) = \mathbb{E}_{x \sim \mathcal{D}}\; \mathbb{E}_{\tau \sim \pi_\theta(\cdot \mid x)}\big[R(x, \tau)\big]$$

这里 \(\mathcal{D}\) 是任务的分布。这个外层期望在推导里不起什么作用，后面为了简洁会省略它；但请记住它的存在，到后面讨论“训练题目怎么选”时，它会变成主角。

4.4和 SFT 的两点不同

把 RL 的设定和 SFT 放在一起看，有两点根本区别。

数据来自模型自己。SFT 从固定的数据集里读答案。RL 让模型自己写，写完再打分。模型变了，它写出的东西也会变，训练数据随之改变。这让 RL 能接触到模型自己真正会走到的状态，代价是训练过程中必须不断地生成，而生成很慢。

反馈只有一个数，而且来得很晚。SFT 在每个位置都告诉模型正确答案是什么。RL 只在最后给一个分数，不说哪个 token 写错了，也不说应该怎么写。从这一个数里，模型要自己弄清楚哪些选择是好的。

第二点是强化学习一切困难的来源。本篇先解决最基本的问题：只有一个分数，梯度从哪里来。

5策略梯度

5.1梯度传不过去

想最大化 \(J(\theta)\)，最直接的办法是求 \(\nabla_\theta J\)，然后做梯度上升。\(\nabla_\theta J\) 问的是：把参数微调一点点，通过率会变多少？

在 SFT 里，类似的问题很好回答。从参数到 loss 的路径是：参数 → \(h\) → logit → softmax 概率 → \(-\log p_k\)。每一步都是连续的公式：参数动一点，logit 就动一点，概率和 loss 也跟着动一点。每一步都能写出局部导数，链式法则把它们连乘起来，就是反向传播。

RL 的路径更长：参数 → logit → softmax 概率 → 采样出 token → 拼成代码 → 跑测试 → 奖励。前三步和 SFT 一样，问题出在加粗的两步。

第一处断点：采样。假设 if 的概率是 0.29。采样可以想象成：从 0 到 1 之间随机抽一个数 \(r\)，如果 \(r < 0.29\) 就选 if。现在把 if 的概率调到 0.30，看同一个随机数下，这一次的输出会怎样：

随机数 \(r\)概率 0.29 时概率 0.30 时
0.10ifif
0.295不是 ifif
0.80不是 if不是 if

绝大多数情况下，输出完全不变，导数是 0；极少数情况下，输出突然从一个 token 跳到另一个，中间没有过渡，导数不存在。“这一次抽出了哪个 token”对概率来说是一个台阶，而不是一条平滑的曲线。导数要么是 0，要么不存在，都无法告诉我们参数该往哪边调。

SFT 没有这个问题，因为它不采样。它直接看目标 token 的概率 \(p_k\)：概率从 0.29 变到 0.30，loss 就从 \(-\log 0.29\) 平滑地变到 \(-\log 0.30\)。

第二处断点：跑测试。即使绕开采样，后面还有测试。测试是一个 Python 解释器加上 assert mean([]) == 0 这样的检查，它不是计算图里的节点，没有“输入变化 0.01，输出变化多少”的公式。更根本的是，它的输入是代码，而代码是离散的：没有一段代码“介于 if not xs 和 if xs is None 之间”。它的输出也是离散的，只有 0 和 1。

所以不能像 SFT 那样，把 \(R\) 当作 loss 直接反向传播。写成代码，(-R).backward() 什么也做不了：\(R\) 只是测试程序返回的一个数，在计算图里和参数没有任何连接。

出路：平均值是平滑的。单次采样的结果会跳变，但平均结果不会。回到 4.3 节的表：把 if not xs: return 0 的概率从 0.20 提高到 0.21，同时从某段失败代码那里挪走 0.01，通过率 \(J\) 就从 0.30 平滑地变成 0.31。这就像投篮：某一次投篮只有进或不进，不会连续变化；但动作一点点改进，命中率可以从 30% 平滑地涨到 31%。

所以思路是：不对“抽到了什么、测试结果是什么”求导，而是对“写出各段代码的概率”求导，再用奖励给这些概率加权。奖励不负责传递梯度，只负责说明哪些代码的概率该提高、哪些该降低；梯度只沿着概率那一段回传，而那一段和 SFT 一样可微。下一节把这个思路写成公式。

5.2换一个角度写期望

从 4.3 节的求和形式出发：

$$J(\theta) = \sum_\tau \pi_\theta(\tau)\, R(\tau)$$

4.3 节已经指出：\(R(\tau)\) 和 \(\theta\) 无关，参数 \(\theta\) 唯一能影响的，是每段代码被写出来的概率 \(\pi_\theta(\tau)\)。

所以求梯度时，\(R\) 可以当成常数，梯度只作用在概率上：

$$\nabla_\theta J = \sum_\tau R(\tau)\, \nabla_\theta \pi_\theta(\tau)$$

这就是上一节的思路落到公式上：两处断点都被绕开了。我们不再需要对采样结果或测试程序求导，只需要对“写出某段代码的概率”求导，而这个概率是模型直接算出来的，完全可微。

这个式子的含义也很直观：要提高平均分，就把高分轨迹的概率推高。每段代码的概率梯度，用它的奖励加权。奖励是 0 的代码，对梯度没有贡献；奖励是 1 的代码，它的概率会被推高。

5.3求和算不完

但这个式子还不能用。它要对所有可能的轨迹求和。词表有十几万个 token，长度 100 的序列就有 \(10^{500}\) 种以上的可能，根本无法枚举。

如果它是一个期望，事情就好办了：期望可以通过采样来估计。抽几个样本，算平均，就是期望的估计值。问题是，上面的式子里每一项的形式是 \(R \cdot \nabla \pi\)，前面没有概率 \(\pi\) 做权重，不是一个期望的形式。

这里需要一个小技巧。根据对数的导数 \(\nabla \log f = \nabla f / f\)，可以把 \(\nabla \pi\) 写成：

$$\nabla_\theta \pi_\theta(\tau) = \pi_\theta(\tau)\, \nabla_\theta \log \pi_\theta(\tau)$$

这叫 log-derivative trick（对数导数技巧）。代回去：

$$\nabla_\theta J = \sum_\tau \pi_\theta(\tau)\, R(\tau)\, \nabla_\theta \log \pi_\theta(\tau)$$

现在每一项前面都有了 \(\pi_\theta(\tau)\)，整个求和就是一个期望：

$$\boxed{\;\nabla_\theta J = \mathbb{E}_{\tau \sim \pi_\theta}\Big[\, R(\tau)\, \nabla_\theta \log \pi_\theta(\tau) \,\Big]\;}$$

这就是策略梯度定理。它说的是：期望奖励的梯度，等于“奖励乘以对数概率的梯度”在模型分布下的期望。

这个技巧乍看像是变魔术，其实只是把一个因子乘进去又除出来。它的意义在于：期望可以用模型自己的采样来估计，而模型自己采样恰好是我们能做的事。

5.4拆回 token

\(\log \pi_\theta(\tau)\) 是整段输出的对数概率。由 1.4 节，它等于每个 token 对数概率之和：

$$\nabla_\theta \log \pi_\theta(\tau) = \sum_{t=1}^{T} \nabla_\theta \log \pi_\theta(a_t \mid s_t)$$
旁注：环境的部分会消失

在 agent 任务里，状态转移不只是“把 token 接到后面”，还包括工具返回的结果、环境的变化。这时轨迹的概率是模型的选择概率和环境的转移概率的乘积：

$$\pi_\theta(\tau) = \prod_t \pi_\theta(a_t \mid s_t) \cdot P(s_{t+1} \mid s_t, a_t)$$

取对数后，环境转移那一项变成 \(\sum_t \log P(s_{t+1} \mid s_t, a_t)\)。它和 \(\theta\) 无关，求梯度时直接消失。这意味着：我们不需要知道环境是怎么运作的，也不需要对环境求导。只需要知道模型在每一步选了什么、选的概率是多少。这是策略梯度能用在任意环境上的根本原因。

于是梯度变成：

$$\nabla_\theta J = \mathbb{E}_{\tau \sim \pi_\theta}\Big[\, R(\tau) \sum_{t=1}^{T} \nabla_\theta \log \pi_\theta(a_t \mid s_t) \,\Big]$$

5.5REINFORCE

用采样代替期望：让模型写一段代码，跑测试得到 \(R\)，然后按下式更新。写成 loss 的形式（取负号，因为优化器做的是最小化）：

$$\mathcal{L}_{\text{RL}} = -\,R \cdot \sum_{t=1}^{T} \log \pi_\theta(a_t \mid s_t)$$

这个 loss 什么时候算、什么时候更新，需要说清楚。一次 REINFORCE 更新分三个阶段，顺序是固定的：

  1. 生成：只采样，不更新。模型按当前的概率一个 token 一个 token 地写，直到写完整段代码。每个位置选了哪个 token、当时的概率是多少，都记录下来。这个过程中参数始终不变。
  2. 打分：把写完的代码拿去跑测试，得到 \(R\)。
  3. 更新：一次性处理整条路径。把每个位置记录下的 \(\log \pi_\theta(a_t \mid s_t)\) 加起来，乘以 \(R\) 得到 loss，做一次反向传播和一次参数更新。所有位置的梯度在这一次反向传播里同时算出来。

所以模型不会“写一个 token 就改一次”。写到第 1 个位置时，模型还不知道这段代码最终能否通过，自然也不知道该推高还是压低这个选择。只有拿到 \(R\) 之后，回头看整条路径，才能决定每个位置该怎么调。这之所以可行，是因为第 1 个位置的梯度只取决于两件事：当时选了哪个 token，以及最终的 \(R\)。前者在生成时已经记下，后者打分后才知道。

这就是 REINFORCE 算法，Williams 在 1992 年提出。现在把它和 SFT 的 loss 并排放在一起：

$$\mathcal{L}_{\text{SFT}} = -\sum_{t=1}^{T} \log \pi_\theta(y_t \mid x, y_{<t})$$

它们只有两处不同：

  1. SFT 里的 token \(y_t\) 是标准答案在第 \(t\) 个位置的目标 token；RL 里的 token \(a_t\) 来自模型自己的采样。
  2. RL 多了一个权重 \(R\)。
最基础的强化学习，就是对模型自己写出的答案做 SFT，再按奖励决定这条答案学多少。

计算图上，\(R\) 是一个普通的标量，不参与求导。梯度全部来自 \(\log \pi\)，而 \(\log \pi\) 的计算和 SFT 完全一样。所以 RL 的训练代码几乎可以复用 SFT 的全部基础设施，只是多了“生成”和“打分”两步。

5.6每个 token 受到什么影响

回到单个位置。2.2 节算过，\(\log p_k\) 对 logit 的梯度是 \(\mathbb{1}[i = k] - p_i\)。在 REINFORCE 里，这个梯度再乘以 \(R\)：

$$\Delta z_i \;\propto\; R \cdot \big(\mathbb{1}[i = a_t] - p_i\big)$$

其中 \(a_t\) 是模型在这个位置实际选的 token。这个更新发生在整段代码写完、拿到 \(R\) 之后，对轨迹里的每个位置同时进行。和 SFT 的唯一区别是：被推高的不是标准答案里的目标 token，而是模型刚才自己选的那个 token，推的力度再乘以 \(R\)。

  • 如果 \(R = 1\)：沿途每个位置上，模型选过的 token 都被推高，就像把这段代码当成标准答案做了一次 SFT。
  • 如果 \(R = 0\)：梯度乘以 0，什么也不发生。

注意，同一条轨迹里的每一个 token 都乘以同一个 \(R\)。代码通过了测试，模型不知道是哪个 token 起了作用，于是所有 token 一起被推高，包括那些无关紧要的。这个问题叫功劳分配（credit assignment），后面会专门讨论。

6用采样估计梯度

6.1一次采样的估计

REINFORCE 用一次采样代替期望。一次采样的结果显然是有偏差的。比如采到一段失败的代码，梯度是 0；采到一段成功的代码，梯度只推高这一段。单看一次，它和真实梯度可能相差很远。

  • 采到失败的补丁时，“这一次的估计”整行都是空的：\(R = 0\)，梯度为 0。
  • 采到成功的补丁时，它被推高，其他三个都被压低，包括另一个同样成功的补丁。这是因为概率此消彼长：推高一个，就一定压低其他。

单看一次，估计和真实梯度差得很远。但多点几次“再采 100 次”，平均值会越来越接近黄色竖线：两个成功的补丁被推高，两个失败的被压低。

6.2真实梯度是什么

这个例子小到可以直接算出真实梯度。4 个补丁的概率是 \(p = (0.2, 0.3, 0.1, 0.4)\)，奖励是 \(R = (1, 0, 1, 0)\)。通过率 \(J = 0.2 + 0.1 = 0.3\)。

对第 \(k\) 个补丁的 logit 求导，可以化简为：

$$\frac{\partial J}{\partial z_k} = p_k \,(R_k - J)$$

代入数值：

补丁\(p_k\)\(R_k\)\(p_k(R_k - J)\)
if not xs: return 00.21+0.14
if xs is None: return 00.30−0.09
return … if xs else 00.11+0.07
return sum(xs) / len(xs)0.40−0.12

这张表里藏着一个以后会反复出现的结构：\(R_k - J\)，也就是“这个补丁的得分，比平均水平高多少”。比平均好的被推高，比平均差的被压低，力度再乘以它当前的概率。

真实梯度里已经有了“和平均水平比较”的意思，但 REINFORCE 的单次估计里没有，它只用了 \(R\) 本身。所以单次估计里，失败的补丁永远是 0，成功的补丁会把所有其他补丁都压低。只有平均很多次之后，“和平均比较”的效果才显现出来。这就是 REINFORCE 噪声大的原因，第 8 节会继续讨论。

6.3无偏，但方差大

用统计的语言说：REINFORCE 的梯度估计是无偏的，它的期望恰好等于真实梯度；但它的方差很大，单次估计离真实值可能很远。

方差大意味着两件事。第一，需要更多样本才能得到可靠的方向，每个样本都要模型完整生成一次再跑测试，成本很高。第二，如果样本不够，每一步更新的方向都在乱跳，训练会很慢，甚至不稳定。

后面要讲的大部分改进，比如基线、优势值、价值模型，核心目标都是同一个：在保持无偏的前提下，把方差降下来。

7训练一个修 bug 的模型

现在把前面的东西全部用上。下图是模型所有可能写出的补丁。它先选第一个 token（if、return 或 try），再选后面的写法。线的粗细表示概率；每个补丁右边标着测试结果，以及模型写出它的概率，也就是整条路径上概率的乘积。

先点几次“采样一次”，逐步看清楚一次更新发生了什么。然后点“连续训练 200 步”，看通过率怎么变化。

7.1一次更新的细节

以采到 return sum(xs) / len(xs) if xs else 0 为例。模型先在位置 1 抽到 return（概率 0.55），再在位置 2 抽到 “… if xs else 0” 这个分支（概率 0.25），整段代码写完后跑测试，通过了，\(R = 1\)。这时才开始更新。

这条路径上有两个决策点。下面两条描述的是同一次更新里两个位置各自的变化，它们同时发生，没有先后之分：

  • 位置 1 选的是 return。按 5.6 节的公式，return 的 logit 增加 \(0.5 \times (1 - 0.55) = 0.225\)，if 和 try 分别减少 \(0.5 \times 0.30\) 和 \(0.5 \times 0.15\)。更新后，位置 1 的分布从 \((0.30, 0.55, 0.15)\) 变成约 \((0.24, 0.63, 0.13)\)。
  • 位置 2 选的是 “… if xs else 0” 这个分支。它的概率从 0.25 变成约 0.41。

整条路径的概率从 \(0.55 \times 0.25 \approx 0.14\) 升到约 \(0.63 \times 0.41 \approx 0.26\)，几乎翻倍。通过率从 41% 升到约 49%。

注意一个副作用：位置 1 的 return 被推高了，但 return 下面还有一个错误的分支 return sum(xs) / len(xs)。它的路径概率是 \(0.63 \times 0.59 \approx 0.37\)，比更新前的 \(0.55 \times 0.75 \approx 0.41\) 低了一些，但它的“入口”变宽了。一个好结果把沿途所有选择都推高，而其中的某些选择也通往坏结果。这就是 5.6 节说的功劳分配问题，在这个小例子里已经能看到。

7.2连续训练

在默认设置下连续训练，通过率会从 41% 左右一路涨到接近 100%。整个过程中，我们从没告诉模型正确答案是什么。它只是不断地写，被打分，强化写对的那些。

多重置几次会发现，最后胜出的写法每次可能不一样，有时是 if not xs，有时是 try，有时是 return … if xs else 0。哪一种胜出，取决于早期碰巧先采到了谁：先被推高的写法，之后更容易被采到，于是被推得更高。RL 不在乎用哪种写法，只在乎测试能不能过。这正好对应 3.1 节的问题：正确答案不止一个时，RL 不会压低其他正确写法。

但这个现象也有另一面：一旦某种写法占据主导，其他正确写法的概率会被持续压低，最终几乎消失。模型的输出变得越来越单一。这叫熵坍缩（entropy collapse），在大模型 RL 里是一个真实存在的问题：模型失去了多样性，也就失去了继续探索的能力。

旁注：这个模型简化在哪里

为了能画出来，图 5 里每个分叉点有自己独立的 logit，互不影响。真实模型所有位置共享同一套参数（2.5 节），推高一处会牵连别处。此外，真实的补丁有成百上千种，而不是 5 种。但核心机制完全一样：采样、打分、按奖励推高这条路径上每个被选中的 token。

8REINFORCE 的三个问题

REINFORCE 能工作，但很粗糙。改一改图 5 的设置，可以看到三个问题。

8.1失败的尝试被浪费了

默认设置下，模型写出错误补丁时 \(R = 0\)，梯度乘以 0，什么都不发生。图 5 的日志里会写“什么都不变”。

这很浪费。一次失败其实包含信息：“这样写不行”。如果能利用这个信息，把错误补丁的概率压低，学习会快得多。可 REINFORCE 只会推高，不会主动压低。错误补丁的概率下降，只是因为别的补丁被推高后，它被动地分到了更少的概率。

在初始通过率很低的时候，这个问题尤其严重：绝大多数采样都失败，绝大多数计算都白费了。

8.2绝对分数没有意义

把“失败时的奖励”改成 0.5 再训练。这相当于告诉模型：失败也有 0.5 分。

单步观察会看到，错误补丁也被推高了，日志会提示“错误补丁也拿到了正奖励，被推高了”。训练最终还是会收敛，因为成功的补丁被推得更多（1 对 0.5），但过程更慢、更抖。

问题在于：奖励的绝对值本身没有意义。0.5 分算好还是算差？如果平均水平是 0.3，那 0.5 是好的；如果平均是 0.8，那 0.5 就是差的。真正有用的信息是：这一次比平时好还是差。

6.2 节的真实梯度里，已经出现了 \(R_k - J\) 这个结构。这启发了一个简单的改进：不直接用 \(R\)，而用 \(R\) 减去一个“平均水平” \(b\)：

$$\mathcal{L} = -\,(R - b) \sum_{t} \log \pi_\theta(a_t \mid s_t)$$

这样，比平均好的轨迹（\(R > b\)）被推高，比平均差的（\(R < b\)）被压低。失败也能提供信号了，8.1 节的问题也一起解决了。

但减去一个 \(b\)，会不会改变梯度的方向，让我们优化错了目标？不会。只要 \(b\) 不依赖于采到的是哪条轨迹，减去它不改变梯度的期望。证明只需要一行：

$$\mathbb{E}_{\tau \sim \pi_\theta}\big[\, b \, \nabla_\theta \log \pi_\theta(\tau) \,\big] = b \sum_\tau \pi_\theta(\tau) \frac{\nabla_\theta \pi_\theta(\tau)}{\pi_\theta(\tau)} = b\, \nabla_\theta \sum_\tau \pi_\theta(\tau) = b\, \nabla_\theta 1 = 0$$

最后一步用到了：所有轨迹的概率加起来永远是 1，对常数求导是 0。直观地说，所有概率的总和不能变，所以“把所有轨迹一起推高”这件事在期望上什么都没做。

减去 \(b\) 不改变期望，却能大幅降低方差。这个 \(b\) 叫做基线（baseline），\(R - b\) 叫做优势值（advantage）。怎样选 \(b\) 最好，是下一篇的起点，GRPO 和 PPO 的主要区别也在这里。

8.3采不到就学不会

把“初始模型”改成“几乎只会写错误补丁”。这时模型写出正确补丁的总概率只有约 4%。

连续训练几次，你会看到通过率在很长时间里几乎不动，然后在某个时刻突然起飞。原因很简单：模型很难采到正确的补丁，也就很难得到任何奖励。没有奖励，就没有梯度。直到某一次运气好采到了正确补丁，它被推高，之后更容易被采到，形成正反馈，曲线才开始上升。

这揭示了强化学习的一个根本性质：

强化学习只能强化模型已经能做到、只是做得不稳定的事情。模型从来写不出来的东西，永远拿不到奖励，也就永远学不会。

有一个常用的指标可以衡量“能不能采到”：pass@k，即采样 \(k\) 次至少有一次成功的概率。如果单次成功率是 \(p\)，那么：

$$\text{pass@}k = 1 - (1 - p)^k$$

单次成功率 4% 时，pass@1 是 4%，pass@16 约 48%，pass@64 约 93%。也就是说，即使模型平均表现很差，只要对同一道题多采几次，还是有机会采到正确答案，RL 就有东西可以学。

这个性质直接决定了大模型训练的几个惯例：

  • 先 SFT，再 RL。SFT 负责把模型带到“偶尔能做对”的位置，RL 负责把“偶尔”变成“稳定”。没有 SFT 冷启动，很多任务上 RL 根本启动不了。
  • 筛选题目难度。模型永远做不对的题，采多少次都没有奖励，等于白算。模型每次都能做对的题，也没什么可学的（下一篇会看到，加了基线之后它的信号恰好是 0）。最有价值的，是模型有时对、有时错的题。
  • 每道题采多个样本。这既是为了提高采到正确答案的机会，也是为了估计“平均水平” \(b\)。下一篇讲 GRPO 时会看到，这两个目的是同一件事。

9完整的训练循环

把前面的内容写成代码。下面是一个最简的 REINFORCE 训练循环，形式上接近 PyTorch，省略了工程细节：

for step in range(num_steps):
    prompts = sample_tasks(batch_size)

    # 1. 采样：模型自己写，不需要梯度
    with torch.no_grad():
        completions = policy.generate(prompts, temperature=1.0)

    # 2. 打分：跑测试，得到每条轨迹的奖励
    rewards = torch.tensor([run_tests(p, c) for p, c in zip(prompts, completions)])

    # 3. 重新计算 log 概率：这一次需要梯度
    #    logp 形状为 [batch, seq_len]，mask 只保留模型生成的 token
    logp = policy.token_log_probs(prompts, completions)

    # 4. REINFORCE loss：每个 token 的 log 概率乘以整条轨迹的奖励
    loss = -(rewards[:, None] * logp * mask).sum() / batch_size

    loss.backward()
    optimizer.step()
    optimizer.zero_grad()

逐行对照前面的内容：

  • 第 1 步是 4.4 节说的“数据来自模型自己”。生成时不需要梯度，可以用专门的推理引擎来做，速度快得多。
  • 第 2 步是 5.1 节说的“断开的路径”。测试在计算图之外，rewards 只是一组普通的数。
  • 第 3 步重新做一次前向，算出每个被选中 token 的 \(\log \pi\)。这一步和 SFT 计算 loss 的过程完全一样，只是 token 来自模型自己的输出。
  • 第 4 步就是 5.5 节的 loss。rewards[:, None] 把每条轨迹的奖励广播到它的所有 token 上，对应 5.6 节说的“每个 token 乘以同一个 R”。mask 把 prompt 部分排除在外，因为 prompt 不是模型的动作。

这个循环里有两个地方值得提前注意。

生成和训练是两套计算。第 1 步用推理引擎生成，第 3 步用训练框架重新算概率。理论上两者算出的概率应该完全一致，但实际上，不同的计算内核、数值精度、批处理方式都可能带来细微差别。在大规模训练中，这种差别会累积成训练不稳定。前沿实验室在“训练和推理的数值对齐”上花了很大力气，原因就在这里。

生成很慢，而且长短不一。第 1 步通常占了整个循环的大部分时间。如果每批样本必须全部生成完才能训练，最长的那条会拖住所有人。agent 任务里，一条轨迹可能要跑几十分钟，这个问题会变得非常尖锐，异步训练就是为它而生的。

10小结与练习

10.1小结

  • 语言模型在每个位置输出一个概率分布。一段输出的概率是每个位置概率的乘积，取对数后变成求和。
  • SFT 最小化整段标准答案的负对数概率，也就是每个位置目标 token 的负对数概率之和。单个位置对 logit 的梯度是 \(\mathbb{1}[i = k] - p_i\)：推高目标 token，按概率比例压低其他 token。
  • SFT 需要唯一的标准答案，上限是示范者，而且只在“前面都对”的状态下训练，导致误差在长序列上累积。
  • 强化学习的目标是最大化期望奖励 \(J(\theta) = \mathbb{E}[R]\)。奖励来自外部，不可导。
  • 策略梯度定理把梯度写成 \(\mathbb{E}[R \cdot \nabla \log \pi]\)：奖励只是权重，梯度来自模型自己的对数概率。环境的转移概率与参数无关，在梯度中消失。
  • REINFORCE 用单次采样估计这个期望。它等价于对模型自己的输出做 SFT，并按奖励加权。估计是无偏的，但方差很大。
  • REINFORCE 有三个问题：失败样本不提供信号，奖励的绝对值没有意义，采不到正确答案就学不会。前两个可以靠减去基线解决，第三个需要 SFT 冷启动和合适的题目难度。

10.2练习

练习 1　logit 为 \((2, 1, 0)\) 和 \((12, 11, 10)\) 时，softmax 概率分别是多少？logit 为 \((4, 2, 0)\) 呢？
参考答案

前两组概率相同，都约为 \((0.665, 0.245, 0.090)\)，因为它们只差一个常数。第三组约为 \((0.867, 0.117, 0.016)\)：logit 差距翻倍，相当于温度减半，分布变得更尖。

练习 2　某位置的概率是 \(p = (0.5, 0.3, 0.2)\)，目标 token 是第二个 token。写出交叉熵 loss 对 3 个 logit 的负梯度，并验证它们的和为 0。为什么和一定是 0？
参考答案

负梯度是 \((-0.5,\; 0.7,\; -0.2)\)，和为 0。因为 softmax 对“所有 logit 加同一个常数”不敏感，loss 在这个方向上没有变化，所以梯度在这个方向上的分量（也就是所有分量之和）必须是 0。

练习 3　如果不管模型写什么，奖励都是 1，REINFORCE 的期望梯度是多少？单次采样的梯度呢？这说明了什么？
参考答案

期望梯度是 0，由 8.2 节的推导，\(\mathbb{E}[\nabla \log \pi] = 0\)。但单次采样的梯度不是 0：它会推高刚才采到的那条轨迹。所以即使奖励完全没有信息，REINFORCE 也会让模型随机地朝某个方向漂移，这就是方差的来源。减去基线 \(b = 1\) 后，每次的梯度都恰好是 0。

练习 4　把奖励改成“通过得 +1，失败得 −1”，和“通过得 1，失败得 0”相比，有什么区别？
参考答案

新奖励 \(R' = 2R - 1 = 2(R - 0.5)\)，相当于原奖励减去基线 0.5，再把学习率乘以 2。失败的轨迹现在会被主动压低。如果模型的通过率恰好在 50% 附近，0.5 是一个不错的基线；但如果通过率是 5% 或 95%，这个固定的基线就离平均水平很远，效果会差很多。这正是需要自适应基线的原因。

练习 5　模型在某道题上的单次通过率是 2%。每道题采 16 个样本，至少采到一个正确答案的概率是多少？如果想让这个概率超过 90%，大约需要采多少个？
参考答案

\(1 - 0.98^{16} \approx 27.6\%\)。要超过 90%，需要 \(0.98^k < 0.1\)，即 \(k > \ln 0.1 / \ln 0.98 \approx 114\)。每个样本都要完整生成并跑测试，这说明了为什么太难的题在 RL 中性价比很低。

练习 6　在 agent 任务中，模型调用搜索工具，工具返回一段网页内容。为什么策略梯度里不需要对“工具返回什么”求导？如果把工具返回的内容也算进 \(\sum_t \log \pi_\theta\)，会发生什么？
参考答案

工具的输出由环境决定，它的概率与 \(\theta\) 无关，在 5.4 节的旁注里已经看到它在梯度中消失。如果把工具返回的 token 也算进 loss，就等于让模型去“学习写出这段网页内容”，并按奖励加权。这不是模型的动作，学它没有意义，还会干扰模型真正该学的东西。所以实际训练中要用 mask 把这部分排除，和第 9 节代码里排除 prompt 是同一个道理。
